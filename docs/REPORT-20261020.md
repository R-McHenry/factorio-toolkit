## New since the first report

- **Router** (`fkcore/route.py`): it wraps v4's tree router (`fkcore/steiner.py`, copied verbatim).
  - **Tree shapes.** A 1 -> k net grows with splitters; a k -> 1 net grows from the consumer and is laid reversed, as merges. A single machine at either end gets direct insertion, fast inserters first.
  - **What it routes around.** Every row frame (kept free for poles), the other nets' end tiles, and every tile another net's belt points into.
  - **Re-routing.** Committed routes whose ends didn't move are pinned, so moving one row re-routes only what it touches (tested: labs moved, packs re-routed, at least 10 nets kept).
- **Flow** (`fkcore/flow.py`):
  - **Checkpoints.** `--from/--to` runs part of the script, starting from the last checkpoint.
  - **Stopping.** `stop_on` stops the run on the named checks; only invariants stop it by default.
  - **Pinning.** `place` keeps a cover's pinned poles, so a merge moves nothing.
  - **Reports.** `report_rates` checks the surface targets; `report_checks` lists every check line of the run.
- **Surface** (`fkcore/surface.py`): the surface file of CORE-V1 §11 parses as written. `cover.bridge` lays shared pole bridges in sanctioned space only.
- **Literal import** (`fkcore/literal.py`): `Literal<file="plant-w3.json", box=...>` imports the kickoff plant. Water and steam become two pipe nets, and each inserter is its own net.
- **Merge** (`fkcore/merge.py`): merge, insert, chests-to-net and net-to-chests. They edit `.fk`, `.fkp` and the surface file only.
- **Sensing** (`fkcore/scene.py`, `fkcore/sense.py`):
  - **Scene model.** v4's scene model is kept, with `last_user` added. The design adapter now reads `compose.Surface`.
  - **Attention.** `sense` reads only the area it is given.
  - **Command.** `python -m fkcore sense GAME CAPTURE.json --area ...` writes marks with `--write-marks`.

## Findings (reported, not detoured on)

1. **Pole wires are not recorded anywhere** (from the power worker). Not in the `.fkp`, not in the blueprint. One wire network depends on the game auto-wiring poles that robots build. This needs a check in the game before the first apply. If it is wrong, the codec has to write `wires`.
2. **A miner row against a frame edge can't be powered.** v5 dropped v4's pole rows from the stamps, so a row's inner drills need a free tile beside the row. `games/redgreen` leaves rows 0-1 free and reaches 185/185. The old `games/spm10/redgreen.fkp`, with its miners at the edge, gets 183/185, and the worker proved by brute force that no spot can reach the two dark drills. Either the template reserves the pole lane or placement has to (my pick: the template, as a fragment role).
3. **The v4 rate rule's deadlock has a router twin.** Routing nets one at a time needs a retry order: redgreen took 11 passes of moving failed nets first. v4's negotiated congestion (`route_congestion`) is the better fix once factories get denser.
4. **`compose.whose()` truncated negative positions** (`int(-0.5) = 0`), so every tile left of or above the origin was looked up wrong. Found by the nauvis test, where the plant sits at -34,-39. Fixed and tested.
5. **Alert push needs a player per force** (open since the first report). `sense` covers the look-time half of fair play; pushing alerts can only be wired to the game.
6. **The lab scenario hasn't run.** No Lua interpreter on the laptop or on zybo; I didn't install one, and I didn't run the local Factorio install. The test is a lexer that checks the Lua's block structure, plus the rules. The first `/lab` in the game is the real test.
